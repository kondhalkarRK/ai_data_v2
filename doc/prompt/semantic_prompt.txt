TASK 1 — CHANGE: semantic/semantic_loader.py
════════════════════════════════════════════════

ADD these new accessor methods to
SemanticLoader class.
Do NOT change any existing methods.

METHOD 1: get_sql_patterns() → dict
  Returns the sql_patterns top-level
  section from business_glossary.yaml
  Returns {} if section missing

METHOD 2: get_domain_rules() → dict
  Returns the domain_rules top-level
  section from business_glossary.yaml
  Returns {} if section missing
  Structure returned:
  {
    "always_rules": list[str],
    "never_rules": list[str],
    "default_behaviours": list[str]
  }

METHOD 3: get_term_sql_expression(
  term_name: str
) → str | None
  Looks up a specific term by name
  in glossary terms dict
  Returns its sql_expression field
  Returns None if term or field missing
  Case insensitive term lookup

METHOD 4: get_term_calculation_rules(
  term_name: str
) → list[str]
  Returns calculation_rules list for term
  Returns [] if missing

METHOD 5: get_term_time_grains(
  term_name: str
) → dict
  Returns time_grains dict for term
  Only populated for Date/Time term
  Returns {} if missing

METHOD 6: get_all_sql_expressions() → dict
  Returns flat dict:
    term_display_label → sql_expression
  For ALL terms that have sql_expression
  Example:
  {
    "Revenue": "SUM(total_sales)",
    "Units Sold": "SUM(order_qty)",
    "Orders": "COUNT(order_id)",
    ...
  }
  Skip terms with no sql_expression

METHOD 7: get_glossary_hints_for_question(
  question: str
) → list[dict]
  Scans question text for synonym matches
  against all glossary terms.
  
  Logic:
  1. Build synonym → term_name map from
     all terms in glossary
  2. Tokenise question into words and bigrams
  3. For each token check synonym map
     case insensitive
  4. For each match collect:
     {
       "matched_token": str,
       "term_name": str,
       "sql_expression": str | None,
       "calculation_rules": list[str],
       "disambiguation": list[str],
       "time_grains": dict
     }
  5. Deduplicate by term_name
  6. Return list of match dicts
  
  Returns [] if no matches found

TASK 2 — CHANGE: semantic/semantic_context_builder.py
════════════════════════════════════════════════

ADD three new methods.
UPDATE one existing method signature.
Do NOT change any other existing methods.

METHOD 1 — ADD: build_glossary_sql_hints(
  question: str
) → str

  Purpose: scan question for glossary term
  matches and return SQL hint block for LLM.

  Implementation:
  1. Call loader.get_glossary_hints_for_question(
       question
     ) → list of matched term dicts

  2. If no matches: return ""

  3. Build formatted string:

  "───────────────────────────────────────────
  SQL HINTS FROM BUSINESS GLOSSARY:
  ───────────────────────────────────────────"

  For each matched term:

  If term has sql_expression:
    "  '{matched_token}' → use: {sql_expression}"

  If term has time_grains:
    Show each grain:
    "  'month' → use: strftime('%Y-%m', ...) AS month"
    "  'quarter' → use: [full quarter formula]"
    "  'year' → use: strftime('%Y', ...) AS year"

  If term has calculation_rules:
    "  Rules for {term_name}:"
    For each rule (max 3):
      "    • {rule}"

  If term has disambiguation (first item only):
    "  Note: {disambiguation[0]}"

  End with separator line:
  "───────────────────────────────────────────"

  Return full string.
  Wrap entire method in try/except
  Return "" on any exception.

METHOD 2 — ADD: build_domain_rules_block() → str

  Purpose: return formatted domain rules
  from glossary for LLM instruction.

  Implementation:
  1. Call loader.get_domain_rules() → dict

  2. If empty dict: return ""

  3. Build formatted string:

  "───────────────────────────────────────────
  DOMAIN RULES (always follow these exactly):
  ───────────────────────────────────────────"

  always_rules section:
  "ALWAYS:"
  For each rule:
    "  ✓ {rule}"

  never_rules section (if present):
  "NEVER:"
  For each rule:
    "  ✗ {rule}"

  default_behaviours section (if present):
  "DEFAULTS:"
  For each rule:
    "  → {rule}"

  End with separator.

  Return full string.
  Wrap in try/except. Return "" on exception.

METHOD 3 — ADD: build_conversation_context(
  conv_state: dict | None,
  chat_history: str | None
) → str

  Purpose: inject prior conversation context
  for follow-up query awareness.

  Implementation:
  If both conv_state and chat_history are None
  or empty: return ""

  Build string:
  "───────────────────────────────────────────
  CONVERSATION CONTEXT:
  ───────────────────────────────────────────"

  If chat_history (non-empty string):
    "Recent conversation:\n{chat_history}"

  If conv_state dict has prior_metric:
    "Prior metric used: {prior_metric}"

  If conv_state has prior_dimensions (non-empty):
    "Prior dimensions: {joined list}"

  If conv_state has is_followup = True:
    "Note: This appears to be a follow-up query.
     Consider inheriting prior context unless
     user explicitly changes topic."

  End with separator.
  Return string. Return "" on exception.

METHOD 4 — UPDATE: build_full_context(
  question: str,
  df: pd.DataFrame,
  conv_state: dict | None = None,
  chat_history: str | None = None
) → str

  Change ONLY the signature and the
  combination step.
  Keep all existing logic intact.

  Current combination:
  full_context = "\n\n".join([
    base_ctx,
    resolved_ctx,
    column_ctx,
  ])

  NEW combination:
  glossary_hints = self.build_glossary_sql_hints(
    question
  )
  domain_rules = self.build_domain_rules_block()
  conv_ctx = self.build_conversation_context(
    conv_state, chat_history
  )

  blocks = [b for b in [
    base_ctx,
    resolved_ctx,
    column_ctx,
    glossary_hints,
    domain_rules,
    conv_ctx,
  ] if b and b.strip()]

  full_context = "\n\n".join(blocks)
  return full_context
