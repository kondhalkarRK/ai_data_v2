════════════════════════════════════════════
ROOT CAUSE — UNDERSTAND FIRST
════════════════════════════════════════════

THE REAL PROBLEM IS NOT ONE QUESTION.
IT IS A SYSTEMIC ARCHITECTURE GAP.

Current system sends to LLM:
  - Fresh schema every turn
  - Concatenated question string
  - No memory of what SQL worked
  - No memory of what filters applied
  - No memory of what metric was active
  - No memory of what columns were shown

Result:
  Turn 1: User asks complex question
    → LLM generates correct SQL ✅
  Turn 2: User asks simple follow-up
    → LLM hallucinates new SQL entirely
    → Different columns
    → Different metric
    → Different filters
    → Lost all prior constraints
  Turn 3: Another follow-up
    → Even more drift from original intent
  Turn N: Result bears no resemblance
    to what user was exploring

THIS IS THE HALLUCINATION SPIRAL.
Each turn drifts further from user intent.

════════════════════════════════════════════
THE COMPLETE SOLUTION — 3 LAYERS
════════════════════════════════════════════

LAYER 1 — SQL ANCHOR
  The last successful SQL is the anchor.
  All follow-up queries modify the anchor.
  Never replace the anchor on follow-ups.

LAYER 2 — INTENT CLASSIFICATION
  Classify EVERY message before sending
  to LLM into one of 4 intent types.
  Different intent = different prompt.
  Same wrong prompt for all = hallucination.

LAYER 3 — STRUCTURED CONTEXT INJECTION
  Instead of concatenating question strings,
  inject a structured context block that
  tells LLM exactly what state to preserve.

  anchor_limit:
    Extract LIMIT value as integer
  
  Store all in state under sql_anchor_*
  Store raw sql in state["sql_anchor"]
  Increment anchor_turn

ADD function: get_sql_anchor() → dict | None:
  Returns full anchor dict or None
  if no anchor set yet

ADD function: clear_sql_anchor():
  Resets all sql_anchor_* fields to None
  Called when user starts clearly new topic

ADD function: should_use_anchor(question) → bool:
  Returns True if:
    sql_anchor is not None
    AND question is a follow-up pattern
    AND question does NOT signal new topic

  New topic signals (clear anchor):
    "new question", "start over",

    question is longer than 12 words
    AND shares no columns with anchor

WHEN TO SET ANCHOR:
  In nlq_engine.run_query():

LAYER 2 — INTENT CLASSIFICATION
════════════════════════════════════════════

FILE: core/question_normaliser.py

ADD function: classify_followup_intent(
  question: str,
  anchor: dict | None
) → str

Returns one of these 5 intent types:

INTENT 1: "additive"
  User wants to ADD something to result.
  Patterns:
    "add {x}", "include {x}",
    "also show {x}", "with {x}",
    "show {x} as well", "plus {x}",
    "can you add {x}", "and {x} column",
    "show me {x} too"
  Action: Add column to SELECT + GROUP BY
          Keep everything else

INTENT 2: "subtractive"
  User wants to REMOVE something.
  Patterns:
    "remove {x}", "hide {x}",
    "without {x}", "drop {x}",
    "don't show {x}", "exclude {x}",
    "only {x} and {y}" (implies remove rest)
  Action: Remove column from SELECT + GROUP BY
          Keep everything else

INTENT 3: "filter_change"
  User wants to change/add a filter.
  Patterns:
    "only for {x}", "filter by {x}",
    "just {x}", "for {year}",
    "in {month}", "where {x} is {y}",
    "same but for {x}",
    "{year} only", "last month",
    "this year", "for {make}"
  Action: Add/change WHERE clause
          Keep SELECT + ORDER + LIMIT

INTENT 4: "sort_change"
  User wants to change ordering or limit.
  Patterns:
    "top {n}", "bottom {n}",
    "order by {x}", "sort by {x}",
    "highest {x}", "lowest {x}",
    "ranked by {x}", "show {n}"
  Action: Change ORDER BY and/or LIMIT
          Keep SELECT + WHERE + GROUP BY

INTENT 5: "new_question"
  User is asking something genuinely new.
  Signals:
    Question > 10 words with no anchor overlap
    "show me", "what is", "how many"
      without follow-up tokens
    No shared vocabulary with anchor
    User explicitly signals new topic
  Action: Generate fresh SQL
          Set new anchor on success

ALSO ADD: extract_intent_subject(
  question: str,
  intent_type: str
) → str | None

  Extracts WHAT the user is referring to:
  "add make column" → subject = "make"
  "filter by 2023"  → subject = "2023"
  "top 5 only"      → subject = "5"
  "remove colour"   → subject = "colour_name"

  For column names: match against df.columns
  using fuzzy match (lowercase, strip spaces)
  Return actual df column name not user word

FILE: core/nlq_engine.py

ADD function: validate_anchor_preserved( new_sql: str, anchor: dict, intent_type: str ) → tuple[bool, str]:

Checks that modification preserved what it should have preserved.
