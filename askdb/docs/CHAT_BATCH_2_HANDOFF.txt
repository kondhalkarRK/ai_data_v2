POINT 5 — AUTHORITATIVE DEFINITIONS AND CAPABILITIES
The typed compiler reads aggregate expressions from the active Automotive YAML.
Expressions are parsed as one SQLGlot expression. Undeclared columns, unsupported
functions, subqueries, windows inside base formulas and chained expressions are
rejected. The model cannot supply formulas, physical joins or permissions.

Current Automotive measure inventory:
  revenue                 Executable: SUM(total_sales), sales fact.
  units_sold              Executable: SUM(order_qty), sales fact.
  orders                  Executable: COUNT(DISTINCT order_id), sales fact.
  average_selling_price   Executable: aggregate revenue / aggregate units;
                          floating division and NULL for a zero denominator.
  active_salespeople      Executable: COUNT(DISTINCT sales_person_id) in the
                          selected sales records, as currently defined in YAML.
  target_units            Specialized: monthly targets, compatible make/time grain.
  target_revenue          Specialized: monthly targets, compatible make/time grain.

Targets have no approved region/model/dealer allocation. Regional users cannot
query those target measures through this path. Supported actuals can still return
with an explicit target limitation. Targets remain full monthly values; daily
proration is not invented. A missing target stays NULL, not zero.

Semantic definition gap to retain visibly: "Active Salespeople" currently means
salespeople represented in the selected transactions. Its formula does not itself
apply dim_salesman.active=true. An explicit active-status filter is supported and
tested. Changing that business definition requires approval; this batch does not
silently change it.

Capabilities and query policies are included in the compact interpretation context.
All current approved measures are searched/retained in this small pack. Unsupported
configured formulas become definition-only; useful executable measures can return
as a labelled partial result. Unknown measures are rejected, not substituted.

The legacy path remains available behind the disabled execution gate and still
uses its existing plan representation. A drift regression compares its five shared
Automotive formulas against YAML; changing one side alone fails that check. The
new typed path has no duplicate hardcoded business formulas.

POINT 6 — DIRECT COMPILATION
Supported and fixture-verified:
  - Multiple totals/measures; weighted ASP; distinct counts; explicit active filters.
  - Multiple groupings and declared dimension joins, including salesperson names.
  - Rankings, per-group top N, ties, best/worst endpoints and a safe row cap.
  - Member comparisons, exclusions and aggregate-result filters.
  - Actual versus target values, variance and attainment where grain permits.
  - One post-aggregation stage (sum/count/distinct count/average/min/max).
  - Running totals with calendar/fiscal/quarter resets at supported grains.
  - Calendar-bucket moving averages, period growth and contribution share.

Compatible measures share one fact aggregation. Different sources aggregate first
and then join at common grouping keys. Raw sales are never joined to raw targets.
Forward many-to-one/one-to-one joins must use declared primary keys; emitted joins
are checked too. A dealer/home-region join no longer drops additional vehicle joins
or emits duplicate aliases. Disabled/custom unapproved join plans fail closed.

The existing shared executor retains SQL safety checks, EXPLAIN, timeout, limits,
history, ratings linkage and usage tracking. Typed SQL is not automatically rewritten
or repaired into another query. An execution/validation failure does not confirm
conversation state.

SQL is emitted for populated and zero-row executions. For regional users, the SQL
event and stored successful SQL match the scoped statement sent to the connection.
Internal count/coverage columns are removed before returning result rows/charts.
The verified group count is used for a visible "Showing N of M groups" notice.
Two scalar totals are not treated as chart axes.

POINT 7 — PERIODS AND COMPARISONS
Automotive YAML now owns the typed-query calendar/default policy:
  - UTC offset +330 minutes (India); fiscal year starts in April.
  - Undated clear rankings use available history through today in permitted scope.
  - Other undated aggregations clarify rather than guessing a period.
  - Relative current periods end tomorrow, exclusive, using the business date.
  - Partial comparisons default to aligned elapsed periods; full-period comparison
    remains explicit. Same-period-last-year aligns the corresponding inclusive
    calendar date, with a documented Feb 29 -> Feb 28 clamp.

Warehouse MAX(date) is freshness context, not the calendar anchor. Requested periods
and current calendar date remain distinct from latest available data. The compiled
query includes actual observed start/through dates per period/source; those coverage
values are exposed in metadata and context when records exist. This establishes
observed endpoints, not proof that every day within that span is complete.

Period results retain current, baseline, absolute change and percentage change.
Percent change divides by the absolute baseline. Zero/missing baselines produce
NULL percentages. Requested members without records remain missing/NULL; verified
zeros stay zero. Empty scalar sources do not fabricate an aggregate zero.

Moving averages use observed values within the requested number of calendar buckets;
missing buckets are not silently filled with zero. Growth uses the immediately
preceding calendar bucket, not the last available older row.

POINT 8 — CONTINUITY AND CLARIFICATION
Pending and successful requests retain the complete typed scope. A follow-up declares
which fields changed. The server merges those fields rather than accepting model
changes to unrelated measures, grouping, filters or periods. Replacing one filter
field preserves other fields, exclusions and both ends of range filters.

A date-only clarification reply retains all measures and grouping. A new definition
or greeting does not execute the preceding analytical request. Changed member filters
do not intersect an obsolete comparison list. Expired state, turn limits, owner/scope
changes, semantic revisions and revoked entity references are revalidated.

Only successful verified execution confirms the request. Greetings work without a
catalog/provider call. A provider/metadata problem returns unavailable rather than
claiming the user omitted a metric. Real model interpretation remains fallible;
fixture follow-up tests do not prove every live paraphrase avoids clarification loops.

EXPLICIT LIMITS — NO SILENT DOWNGRADE
  - One period baseline with no simultaneous time-grain comparison/window transform.
  - One member-comparison axis; multi-axis comparison needs an aligned plan.
  - Benchmark comparisons need an approved benchmark plan.
  - Cumulative/rolling ASP and other ratios need weighted numerator/denominator plans.
  - Post-aggregation does not silently drop other measures or sum ratios.
  - Compound target/window/member transformation shapes remain unsupported.
  - A small source-plan registry currently covers sales and monthly targets only.
  - Unknown/unavailable entities and over-budget context cannot be assumed correct.
  - The enabled typed path requires AI interpretation for substantive questions;
    it fails visibly on provider failure. Full automatic legacy fallback is not added.
  - Report execution, "why" investigations, "so what" synthesis and document retrieval
    remain gated in the typed path until Batch 3. Recognizing a route is not execution.
  - Detailed executive narration and intent-versus-question validation are not
    declared complete here; these are subsequent acceptance work.
