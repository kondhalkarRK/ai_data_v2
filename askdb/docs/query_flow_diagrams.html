1. End-to-end question flow

Every step a chat question passes through, from login to the admin dashboards.

flowchart TD
    A([User asks in AI Chat]):::user --> B{Logged in?}
    B -- no --> B1[Redirect to /login]:::stop
    B -- yes --> C[Load admin LLM settings
provider, model, temperature, max tokens]:::gov
    C --> D{"Weekly quota left?
USER: 60k tokens / 50 calls
ADMIN: unlimited"}:::gov
    D -- no --> D1[Weekly AI quota reached
contact administrator]:::stop
    D -- yes --> E[Rewrite
spelling fixes and business vocabulary]:::sem
    E --> F{Same question cached?}
    F -- yes --> F1[Return cached answer]:::cache --> U
    F -- no --> G[Understand question
metric, entity, filters, period, analysis type]:::sem
    G --> H[Entity catalog lookup
brands, models, cities, states, synonyms]:::sem
    H --> I{Too ambiguous?}
    I -- yes --> I1[Clarification and suggested questions]:::clar --> U
    I -- no --> J{Route
keyword rules, no LLM}
    J -- knowledge --> K[Search uploaded documents]:::doc --> K1[Narration with citations]:::doc --> U
    J -- sql or hybrid --> L[Load semantic pack
tables, measures, joins, glossary, rules]:::sem
    L --> M{Semantic layer can compile?}
    M -- yes --> N[Compiled SQL
no LLM]:::sem
    M -- no --> O[LLM writes SQL
schema hints + joins + plan]:::llm
    N --> P[Validator]:::val
    O --> P
    P -- fails --> Q[LLM repair]:::llm
    Q --> P
    P -- passes --> R{Confidence OK?}
    R -- low --> I1
    R -- ok --> S[Run read-only on analytics DB]:::exec
    S --> T[Chart, trust score, insights, narration]:::exec
    T --> T1{Hybrid route?}
    T1 -- yes --> T2[Add document citations
filtered by entities]:::doc --> U
    T1 -- no --> U
    U([Answer card with path and confidence badges]):::user --> V[Record usage
tokens, time, execution mode]:::gov
    V --> W[Admin Center dashboards
and user usage meter]:::gov

2. Routing decision (first match wins)

Deterministic keyword rules in query_router.py. The default is always governed SQL, never document search.

flowchart TD
    Q([Question]) --> R1{"Contains document phrase?
summarize, key findings, concerns,
recommendations, in the document,
from the report, policy document"}
    R1 -- yes --> K[KNOWLEDGE
documents only]:::doc
    R1 -- no --> R2{"Explanation phrase?
why, reason, factors, insights,
drivers of, explain the increase"}
    R2 -- yes --> H[HYBRID
SQL answer + document citations]:::hyb
    R2 -- no --> R3{"Plan found a metric, entity,
dimension, filter or analysis?"}
    R3 -- yes --> S[SQL
governed analytics]:::sql
    R3 -- no --> R4{"Documents uploaded AND question
mentions document, report, policy,
memo, catalog?"}
    R4 -- yes --> K
    R4 -- no --> S

3. SQL generation, validation and repair

Compiled SQL is preferred; the LLM is used only when the semantic layer cannot compile the plan. Both paths go through the same validator.

flowchart LR
    P[Question plan] --> C{Supported analysis?}
    C -- "ranking, top-N per group, growth,
moving avg, running total, share,
contribution, divergence,
above average, year compare" --> CS[Compiled SQL]:::sem
    C -- "other, e.g. target vs actual,
custom ratios" --> H[Domain hints
tables, measures, glossary,
rules, relevant joins]:::sem
    H --> L[LLM generates SQL]:::llm
    CS --> V
    L --> V
    subgraph V[Validator]
      direction TB
      V1[Tables and columns in semantic pack]
      V2[Mandatory filter values present]
      V3[Correct entity table
dealer vs salesperson]
      V4[Ranking direction]
      V5[GROUP BY dimensions]
      V6[Window / partition shape]
      V7[Requested period applied]
    end
    V -- fail --> RP[LLM repair with reason]:::llm --> V
    V -- pass --> CF{Confidence}
    CF -- high --> EX[Execute read-only]:::exec
    CF -- low --> CL[Clarify and suggest]:::clar

4. Documents: upload and retrieval

Documents are stored per industry. The knowledge route returns the top 5 passages and narrates the first 3; the hybrid route first filters passages by the entities in the question.

flowchart TD
    subgraph Upload[Upload at /knowledge]
      U1[PDF / DOCX / TXT / MD / HTML] --> U2[Extract text]
      U2 --> U3[Deduplicate by content hash]
      U3 --> U4[Split into chunks
1400 chars, 180 overlap]
      U4 --> U5[Tag entities
brands, cities, segments]
      U5 --> U6[(Knowledge store
per industry)]
    end
    subgraph Ask[Chat question]
      A1{Route} -- knowledge --> A2[Score all chunks]
      A1 -- hybrid --> A3[Keep chunks mentioning
plan entities] --> A2
      A2 --> A4[Top passages as citations]
      A4 --> A5[Narration + citation chips]
    end
    U6 -.-> A2

5. Semantic model vs ontology graph

Chat does not read the Knowledge Graph. Both are built from the same semantic pack, so editing the model changes both.

flowchart TD
    Y[(Semantic pack YAML
tables, relationships, measures,
dimensions, glossary, rules, value lists)]:::sem
    Y --> G[Ontology snapshot
SemanticService.get_snapshot]:::ont
    G --> GV[Knowledge Graph tab
for people: explore and verify]:::ont
    Y --> C1[Entity catalog
value lists and synonyms]:::chat
    Y --> C2[Compiled SQL
measures and joins]:::chat
    Y --> C3[LLM prompt hints
tables, measures, relevant joins, rules]:::chat
    Y --> C4[Validator whitelist
allowed tables and columns]:::chat
    C1 --> CH([AI Chat answer])
    C2 --> CH
    C3 --> CH
    C4 --> CH
    CH --> JP[Join path shown on answer card]:::chat
    JP -. trace it in .-> GV

6. Quota and usage tracking

Checked before the pipeline runs and recorded after it finishes.

sequenceDiagram
    autonumber
    participant U as User
    participant W as Web app
    participant API as Chat API
    participant Q as Quota service
    participant P as Chat pipeline
    participant DB as App DB (llm_usage)
    participant A as Admin Center

    U->>W: Ask question
    W->>API: POST /chat (session cookie)
    API->>API: Load admin LLM settings
    API->>Q: Check weekly tokens and calls
    alt USER over limit
        Q-->>API: quota_exceeded
        API-->>W: 429 friendly message
        W-->>U: Weekly AI quota reached
    else Within limit or ADMIN
        Q-->>API: OK
        API->>P: Run pipeline (stream stages)
        P-->>W: Stages, SQL, rows, insights
        API->>DB: Save one usage row
tokens, time, model, mode
        W-->>U: Answer card
        DB-->>A: Governance, LLM Usage, Audit dashboards
    end

7. How the execution mode is decided

Stored with every question in llm_usage and shown in Admin Center.

flowchart LR
    S([Question finished]) --> C{Cache hit?}
    C -- yes --> M1[CACHE]:::cache
    C -- no --> L{Any LLM call used?}
    L -- no --> M2[SCHEMA]:::sem
    L -- yes --> P{LLM wrote the SQL?
path = semantic_llm}
    P -- yes --> M3[LLM]:::llm
    P -- no --> M4["HYBRID
(compiled SQL + LLM interpret,
repair or narration)"]:::hyb
