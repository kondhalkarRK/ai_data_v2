FILES ADDED
apps/api/app/services/chat/analytical_plan.py
  Strict version-1 proposal contract, maximum four ordered steps.
  Operations: aggregate, select_extreme, select_ranked, compare, contributors,
  history. Approved InterpretedRequest is reused for analytical scope.
  Output roles/types, explicit input/dependency references, entity/period bindings,
  baseline provenance, completeness evidence, opposite-direction change predicates,
  independent reconciliation declarations and requirement-to-output mapping.
  Whole-request model-call limit is two, including initial interpretation.
  All ties retained; selected cohort capped at 50; overflow asks to narrow;
  empty selection skips dependents. Selection must precede display limits.
  These are safety CONTRACTS, not implemented runtime behaviour.

apps/api/app/services/chat/analytical_plan_validation.py
  Pure review returning valid/partial/clarification/unsupported/invalid.
  execution_enabled is always False. Valid means contract review passed, NOT that
  any SQL ran or the answer was proved correct.
  Reviews against a separately supplied expected-requirement inventory; a plan
  cannot establish coverage by comparing only with its own declarations.
  Binds request, authenticated principal/scope and semantic fingerprint; rejects
  stale/foreign/no-access contexts, unapproved measures/fields/entities and formula
  changes. Uses the current pure semantic capability inventory.
  Checks operations, measures, filters/exclusions, grouping, dates, windows,
  comparisons, ranking basis/direction and mapped output roles independently.
  Extra ranking/comparison is rejected because it can change the requested answer.
  Result references preserve field/type, period-boundary order and dependencies.
  History must retain a selected entity cohort and member grouping.
  Additive decline contributors require signed change ranking and a separate
  ungrouped headline with identical scope/baseline/bindings. Ratios are unsupported
  for initial contribution decomposition. No residual is fabricated as proof.
  Completeness sources require a scoped reference and revision. Calendar closure
  alone does not prove loading. Operational evidence must cover the resolved
  selection window. Unknown/insufficient evidence cannot receive a valid plan.
  No MAX(date), warehouse access, provider request, SQL generation or result binding
  occurs. Mutable proposals are schema-revalidated before reference lookup.

apps/api/tests/unit/test_analytical_plan.py
  Visible synthetic contract examples, NOT blind holdouts or reference-SQL tests.
  Five general shapes:
    A. Month totals -> tied minimum month(s) -> independent baseline/headline
       and region-model changes -> reconciliation declaration.
    B. Region totals -> selected extreme region(s) -> rank models inside them.
    C. Period comparison -> rank declines by the requested change basis.
    D. Compare two measures -> filter opposite signed changes.
    E. Rank a fixed cohort -> compare each member with its own history.
  The named lowest-revenue-month regression is included as an explicit contract
  example, with prior-month baseline and combined region-model grouping specified.
  It is not a special-case vehicle/entity parser or a general-language benchmark.
  Negative cases damage proposals while keeping the expected inventory fixed.
  Tripwires cover model calls, compilation, warehouse/app SQL, retrieval and reports.
