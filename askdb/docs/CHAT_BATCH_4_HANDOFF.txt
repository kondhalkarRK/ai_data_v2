13. SECURITY REVIEW AND FIXES
- Existing authentication, server-owned industry/region context, read-only guards,
  scoped connection, SQL validation and row limits are retained. Tests cover scope
  revocation before execution and catalog separation by owner/scope/semantic version.
- Typed context no longer offers email/corporate-ID/credential fields as dimensions
  or candidate filters. This is a bounded field restriction, not comprehensive PII
  detection or automatic masking of every possible sensitive column.
- New typed-preparation/report failure logs omit raw traceback/provider/connection
  details. Analytics execution logs the error class and returns its existing safe
  message, rather than dumping raw SQL exceptions.
- Report cancellation checks run before each next panel. Cancellation does not
  schedule remaining panels. In-flight database work remains bounded by its existing
  execution timeout; a browser Cancel button is not a database termination guarantee.
- Report access is revalidated by existing owner/scope/revision checks, including
  the final access check before returning its panel results.
- Fixed a snapshot integration gap: the report event now populates the snapshot's
  report ID/revision. History access and feedback can enforce report ownership and
  persist the correct report revision. Previously saved report events are also
  inspected when the explicit snapshot report field is absent. Deleted/unowned or
  malformed references fail closed instead of replaying panel values.
- No permission denial triggers another model call or a bypass query.

Data sharing: the interpretation call receives user text, relevant approved semantic
definitions and scoped entity candidates (which can include business/person names).
It does not receive query result rows or the locally generated evidence summary.
Do not claim DDL-only sharing or complete removal of personal information. Provider
retention, private endpoints, database reader permissions and tenant-specific column
classification remain deployment responsibilities. This is not an ASVS certification.

  automatically converted into a different plan. This check does not prove complete
  natural-language understanding or detect every possible lost exclusion/entity.

  New optional .env.example settings (actual .env unchanged):

    CHAT_INVESTIGATION_SQL_TIMEOUT_SECONDS=10
    CHAT_REPORT_WORKFLOW_TIMEOUT_SECONDS=120

  provider's configured completion cap. Reports remain limited to six governed panels.
- Run metadata records initial/correction application-level model calls, input/output
  tokens, estimated usage, interpretation/planning/execution/narration time, analytical
  query attempts, query-cache status and fallback reason. The report meter separately
  counts warehouse statements, including validation/metadata/timeout statements and
  failed attempts. Analytical counting is placed at actual analytical execution.
  Report usage callbacks preserve counts if later work is cancelled.
- Ordinary warehouse-statement count is null when that broader counter is not used;
  the separate analytical-query counter still records its query attempt. Zero is not
  used to imply an unmeasured statement count.
- Metadata is saved with the response and available in the info panel. Application
  call counts are not a claim about low-level HTTP retries or provider billing.
- No real gateway before/after cost or latency comparison was performed. Mock token
  counts verify bookkeeping only; local test duration is not product latency.
