IMPLEMENTED
1. Investigations use the typed request and existing governed compiler/executor.
   Additive measures can be broken down by approved dimensions (region when no
   other breakdown is requested). Missing current periods clarify; a preceding
   period is the disclosed default baseline when a current period is supplied.
   One statement computes both periods, breakdowns and uncapped headline totals
   in the same snapshot. Existing scope, joins, limits and SQL safety still apply.

   Narration says "Contributing factors", shows signed changes and an explicit
   Other / remaining groups residual. Capping the visible groups does not turn
   their sum into the headline. Missing comparison observations are not converted
   into zero: decomposition is marked unverified. Ratios, distinct counts and
   complex transformed investigations need an approved decomposition and return
   a limitation instead of a fabricated reason. No causation is inferred.

2. Typed factual narration is deterministic and reads verified result fields.
   Amounts use the existing INR formatter (rupee, Cr/Lakh); percentage fields use
   percentage formatting and count fields have no currency symbol. No extra model
   or analytical call is made just to enrich prose. Empty results remain distinct
   from zero. Requested definitions are supplied from approved metadata alongside
   analytics. Raw SQL/result/export precision remains unchanged.

   Successful, scope-bound conversation state stores a server-generated evidence
   summary. "So what?" can reuse it, separating observations, implications and
   suggested review actions without another analytical query or operational action.
   Without authorized prior evidence it asks for an analysis first. Suggestions are
   deliberately conservative; this is not an autonomous business action agent.

3. Explicit typed reports hand off to existing AskBI repository, validation and
   execution. The handoff creates governed WorkspaceSpec/BiPlan panels directly,
   rather than reinterpreting the question through another model call. Exact dates,
   supported filters and grouping are carried over. Clear sales reports default
   to revenue/units; missing periods become a persisted focused clarification.

   A typical report has two KPIs and four charts within AskBI's six-panel maximum.
   Requests with more measures use the available panel budget; requested grouping
   beyond the supported budget is rejected rather than silently discarded.
   Only representable filters are accepted. Exclusions/advanced transformations
   unsupported by the handoff return an explicit limitation.

   Existing ownership/scope and optimistic revisions apply. Follow-ups retain the
   report ID and unrelated panel choices; stale Builder revisions are rejected.
   Each panel uses existing AskBI execution/evidence checks. Failure preserves the
   other verified panels with a partial-report notice. Permission denial aborts
   the handoff, and ownership/scope is checked again before returning results.
   Cancellation propagates; a bounded 120-second panel workflow does not loop.

   Chat emits the report ID, revision, panel results and partial status, plus a
   link using the existing askbiReport Builder parameter. Rich rendering of this
   event in both Chat layouts belongs to Batch 4. No new frontend preview component
   was added here. Six existing starter actions, exports and Outlook were untouched.

4. Document retrieval remains disabled in typed Chat. Mixed analytics can return
   its verified database part with unavailable-document/partial notes. Report
   handoffs with document dependencies state that policy compliance is unverified.
   No vector database, embeddings, policy threshold invention or retrieval fallback.
