3. REFERENCE FILE CONTRACT

gold.json is an object keyed by case ID. Ordinary simple questions keep the existing
format from CHAT_BATCH_5_OFFICE_STEPS.txt. Dependent references use these fields:

  route: expected interpreted intent (analytics or investigation)
  text: complete independently approved narration, not a few matching fragments
  reference:
    kind: human_reference
    reviewer: responsible human reviewer identifier
    reviewedAt: review date
    datasetRevision: the frozen warehouse revision
    sqlSha256: SHA-256 of the independently reviewed reference SQL file
    holdout: true only for human-supplied unseen questions; false for known regressions
  analysis:
    status: expected completed/partial/empty/clarification state
    scope: exact permitted scope labels, e.g. ["West"]
    checks: independent reconciliation checks, or [] when not applicable
    unanswered: expected [{"status":"...","reason":"..."}], or []
    steps: every step in execution order, including supporting steps

Each reference step must explicitly include ALL these fields:
  operation: aggregate/select_extreme/select_ranked/compare/contributors/history
  dependsOn: zero-based indexes of required earlier steps; [] for none
  measures: approved measure IDs, in order
  grouping: approved dimension IDs, in order
  filters: [{"field":"approved.field","operator":"eq","values":["reviewed value"]}]
  period: {"start":"YYYY-MM-DD","endExclusive":"YYYY-MM-DD"}
    Use explicit null bounds only for approved all-history scope.
  comparisonPeriods: [{"currentStart":"...","currentEnd":"...",
                       "baselineStart":"...","baselineEnd":"..."}], or []
  baseline: previous_period/same_period_last_year/etc., or null
  status: completed/empty/partial/skipped/clarification
  verified: true/false
  columns: exact output column names, in order
  rows: independently calculated row objects, including every declared column
  totalGroups: independently verified full group count
  selectedGroups: independently verified selected count
  rowOrder: ordered, or unordered only when the reference explicitly permits it

Do not copy Scio's unverified answer into gold. Expected steps are matched by order,
operation and dependency indexes, not by the model's arbitrary internal step names.
All returned fields and all comparison members must be accounted for. Empty arrays
and null baselines must be explicit, not omitted. A missing reference is not a pass.
Reference reconciliation objects use zero-based headlineStep/contributorStep indexes,
the approved measure ID, and passed true/false. Hashes/metadata are reviewer
declarations, not cryptographic proof that a person authored the SQL or a holdout.

Get the reference-file hash locally:
  (Get-FileHash -Algorithm SHA256 -LiteralPath data/staging/dependent-acceptance/reference.sql).Hash.ToLower()

Decimal outputs allow only 0.000001 absolute difference; integer outputs match exactly. No relative
tolerance hides large revenue errors. Decimal strings from PostgreSQL JSON retain
precision during comparison. Text labels, NULL, booleans, duplicates and column sets
remain distinct. Rows are compared in order unless explicitly marked unordered.
