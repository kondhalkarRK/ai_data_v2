26 November 2026
Scope: AskDB Automotive; approved plan points 1-4 only.

WHAT THIS BATCH PROVIDES
1. Versioned InterpretedRequest contract with multiple approved measures, canonical
   entity references, typed filters, exclusions, grouping, explicit/relative periods,
   comparison baselines, partitions/windows/resets, post-aggregation operations,
   measure filters, ranking/ties/both ends, clarification and ordered evidence tasks.
   Original question, run ID and semantic fingerprint belong to the server envelope.
2. Dynamic context gathering from the Automotive pack and an authorized catalog.
   All measures are searched. Relevant model values and approved aliases are included.
   Measure phrases are protected against fuzzy entity confusion. Context overflow
   fails explicitly instead of dropping requested measures/comparison members.
3. One compact LLM interpretation call returning this contract directly, with no
   English restatement/reparse. Server checks references and immutable base formulas.
   Unknown IDs, authority fields, executable SQL and invalid structure are rejected.
4. Pure routing decisions for conversation, general knowledge, definitions, analytics,
   investigation, implications, reports, data quality, prior SQL and gated documents.
   Compound outcomes and unavailable document/report evidence remain explicit.
5. Authenticated first-name greeting fast path; approved definitions use the existing
   metadata lookup. General-knowledge and AskBI flags are respected.

IMPORTANT: THIS IS ROUTING PREVIEW, NOT NEW ANALYTICAL EXECUTION
The new path is disabled by default. Normal /chat/ask and synchronous Chat remain on
the existing shared service. No SQL compiler bridge, new driver calculations,
report creation, retrieval, conversation-state migration or UI redesign is included.
status=ready means valid for routing review, NOT a verified analytical answer.
Every preview returns preview_only=true and execution_enabled=false.
Old Chat interpretation failures are not claimed to be fixed in the live Chat UI yet.

PREVIEW ENTRY POINT
POST /api/v1/chat/route-preview
Body: {"question":"How is revenue defined?"}
Requires a signed-in administrator and the existing auth/CSRF headers.
Gate: CHAT_REQUEST_PREVIEW_ENABLED=false (default; documented in .env.example).
Setting this gate true exposes only the admin preview, not a new execution path.
Insurance returns unavailable/404 and remains unchanged.

The endpoint has NO analytics-connection dependency. It performs no warehouse
queries, retrieval, LLM SQL generation or report creation. It may read the existing
cached entity dictionary for unrestricted admins. With an empty cache, the preview
has semantic context but cannot validate arbitrary entity values. It does not fetch
warehouse values to warm that cache. Restricted admins never consume the global
catalog cache. Scoped catalog acquisition is a required Batch 2 integration task.
The core interpreter accepts an explicitly owner/scope-bound catalog for tests and
future server integration; the HTTP client cannot submit its own catalog or authority.

BUDGETS AND METERING
- One complete_text call, no automatic correction loop or SQL fallback.
- Existing interactive NLQ timeout; existing LLM completion cap, at most 600 tokens.
- Approved context is bounded to 9000 serialized characters; total interpretation
  instructions/input are capped at 16000 characters. These are character bounds,
  not exact provider-token limits. No requested context is silently truncated.
- Provider token usage is retained; missing counts are explicitly marked estimated
  in the preview. Elapsed time, model and call count are exposed for testing.
- Existing quota preparation runs first. Model-backed previews write an existing
  LlmUsage row labelled '[Routing preview]'; no conversation or query result is copied.
- Provider failures return unavailable, not a false missing-measure clarification.
- Cancellation propagates. Outer timeout bounds the call. No live gateway calls were
  performed here; provider compatibility, real latency and token use remain unverified.
